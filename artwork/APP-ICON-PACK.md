# One-Bit Bureau app icon pack

The 32 app-role illustrations are original ImageGen outputs made for One-Bit Bureau on 2026-08-29 and 2026-08-30. Each selected source was generated separately on a transparent canvas with no logos, letters, trademarks, platform marks, gradients, drop shadows, or color beyond warm paper and near-black carbon. Two otherwise successful generations arrived with a baked checkerboard; the Writer and Maps sources were repaired through ImageGen background extraction before they entered the pack.

The shared prompt contract was: an original late-1984-inspired one-bit bitmap illustration for a generic application role, chunky black pixel contours, sparse ordered dithering, warm off-white paper fill, strict frontal or slight three-quarter silhouette, readable at 48–64 pixels, no imitation of a specific historical system icon. The original role set covers Files, Terminal, Web, Code, Mail, Chat, Music, Video, Calendar, Controls, Games, and Notes. The expanded set adds Application, Theme, Document, Disk, Image, Spreadsheet, Presentation, Writer, Transfer, Paint, Video Edit, Broadcast, Calculator, Printer, OCR, Project, Containers, Contacts, Maps, and Social.

`pack.json` is the machine-readable association catalog. Its 36 fresh-install records cover every launcher-visible application shipped by Omarchy Quattro while deliberately mapping related apps to reusable visual roles instead of copying vendor marks. Known apps receive an authored role automatically. An uncommon app with a valid native icon receives that icon in grayscale; an app whose native icon cannot be resolved receives the authored Application fallback; explicit Native mode restores the original icon in color.

`render-app-icons.py` thresholds faint ImageGen alpha, trims the transparent masters, and deterministically produces 256×256 PNGs inside a shared 230×230 optical box. The installed dock consumes only the rendered files under `components/dock/assets/app-icons/`; the source masters remain in `artwork/imagegen/app-icons/` for later hand-pixeling or vectorization.

`video-rejected-source.png` is intentionally not part of the pack. It was rejected because the projected-light form introduced a hand-like ambiguity and a weaker silhouette than the final reel-and-viewer design.
